# nlu/models — 오프라인 스파이크 (폐기 전제)

> 이 디렉터리는 **버릴 것을 전제로 한 실험**만 담는다. Go 통합·계약 변경·마이그레이션은
> 여기서 하지 않는다. 리포 전체에서 Python이 허용되는 유일한 자리다(`.claude/rules/nlu.md`).

## Phase 1 — 임베딩이 검색의 언어 경계를 넘는가 (2026-07-27 착수)

### 무엇을 묻는가

`just eval-search` 25질의 중 **10건이 미발견**이고, 그중 **8건이 언어 경계**다 — 한국어로
기억하는데 문서가 영어다. trigram·LIKE 둘 다 글자 매칭이라 `머신러닝`과 `machine learning`
사이를 못 건넌다. 사전을 키워도 안 된다(사전은 태그 42개를 담는 물건이다).

**다국어 임베딩이 정확히 그 일을 하는 물건이므로, 실제로 하는지 잰다.**

### 왜 태깅이 아니라 검색인가

원안은 임베딩을 **태깅** 앙상블로 넣으려 했다. 그런데 2026-07-27 실측에서 태깅의 재랭킹
여지가 **세 세트 모두 0**으로 확인됐다 — 남은 미스가 전부 "정답 태그가 진짜 0점"이라
순위를 바꿔서 얻을 것이 없다. 거기서 임베딩이 값을 하려면 0점 태그를 **승격**시켜야 하고,
그건 오탐 대량 유입이라는 반대 위험을 진다.

검색은 반대다. **결과가 0건인 질의에 후보를 더하는 것**이라 더 나빠질 여지가 구조적으로
없다 — 이미 넣은 두 수정(FTS AND 재시도, LIKE 낱말 분리)이 쓴 것과 같은 논리다.

### 폐기 기준 — **실행 전에 적는다**

하나라도 걸리면 중단하고, 중단했다는 사실과 수치를 이 파일에 남긴다.

1. **언어 경계 8건 중 3건 미만**을 상위 3위 안에 올리면 폐기. 원안의 "0점 6건 중 3건 이상"과
   같은 비율이고, 그보다 적으면 색인 수정 두 개(합쳐 +8pp)보다 못한 값어치다.
2. **지금 잘 찾는 15건을 건드려야만 이득이 나면** 폐기. 개입은 "FTS·LIKE가 빈손일 때만"으로
   한정할 수 있어야 한다. 그 조건에서 이득이 없으면 하이브리드가 성립하지 않는다.
3. **출하 가능한 크기의 모델로 재현되지 않으면** 폐기 — 아래 참조.

### 크기 제약을 미리 적어 둔다

스파이크에 쓰는 모델은 **출하 후보가 아니다.**

| 모델 | 크기 | 출하 가능? |
|---|---|---|
| `intfloat/multilingual-e5-large` | ~2.2GB | ✗ |
| `paraphrase-multilingual-mpnet-base-v2` | ~1.1GB | ✗ |

제품은 **단일 Go 바이너리 + CGO-free**이고 콜드 스타트 게이트가 1초다. 위 크기는 어느 쪽도
못 만족한다. 그래서 스파이크는 **"의미 매칭이 이 문제를 푸는가"** 만 답하고, "얼마나 작은
모델까지 되는가"는 그 답이 예스일 때 이어서 묻는다. 큰 모델이 실패하면 작은 모델도 실패하므로,
큰 것으로 먼저 상한을 재는 순서가 맞다.

### 결과 (2026-07-27, `paraphrase-multilingual-mpnet-base-v2`)

`intfloat/multilingual-e5-large`는 캐시가 28MB짜리 미완성이라 쓰지 못했다.
대신 같은 캐시에 온전히 있던 `paraphrase-multilingual-mpnet-base-v2`(1.0GB)로 쟀다.

**기준 1: 언어 경계 7건 중 상위 3위 안 = 3건 → 통과(문턱값에서 정확히).**

| 질의 | 임베딩 순위 |
|---|---|
| `습관 만드는 법` → *How to Build a New Habit* | **1위** |
| `판다스 10분 입문` → *10 minutes to pandas* | **1위** |
| `기후 변화 증거` → *The Reality of Climate Change* | **1위** |
| `허깅페이스 트랜스포머 입문` | 16위 |
| `쿠버네티스 하드웨이` | 42위 |
| `고랭 제네릭 언제 쓰나` | **125위** |
| `브랜치 예측 실패 정렬 배열`(본문에만) | 14위 |

**되는 것과 안 되는 것이 뚜렷하게 갈린다.** 사는 것은 **주제가 문장으로 표현된** 질의다
(습관 만들기, 판다스 입문, 기후 변화). 죽는 것은 **음차된 고유명사가 지배하는** 질의다 —
`고랭`·`허깅페이스`·`쿠버네티스`. 그 경우 임베딩 1위가 아예 무관한 문서다
(`고랭 제네릭 언제 쓰나`의 1위가 "중소 신입 개발자 회고", `쿠버네티스 하드웨이`의 1위가
"클리앙 모두의공원"). 모델이 음차 고유명사를 원어와 잇지 못하고, 남은 조사·부사로
아무 한국어 문서나 끌어온다.

### 스파이크가 계측기의 결함을 하나 드러냈다

`파이썬 데코레이터 설명`의 임베딩 1위가 **`daleseo.com`의 「파이썬 데코레이터 기본 사용법」**
이었다. 확인해 보니 그 문서가 코퍼스에 있고, **한국어 질의에 영어 realpython보다 명백히
더 맞는 답**이다. 즉 라벨이 틀렸다 — 게다가 **현재 FTS 검색도 원래 그걸 1위로 내고 있었는데
계측기가 miss로 세고 있었다.**

라벨을 고치자 현재 검색의 실제 기준선이 **hit@1 0.440 → 0.480**으로 올라갔다.
**임베딩이 아니라 계측기를 고쳐서 얻은 숫자다.**

이건 검색 golden의 설계 한계를 드러낸다 — 질의당 정답을 **하나만** 허용한다. 태깅 golden은
`expected_tags`가 여럿인데 여기는 URL 하나다. "다시 찾기"에서 여러 문서가 정답일 수 있으므로
스키마를 복수 허용으로 바꾸는 것이 옳지만, **이번에는 명백한 라벨 오류 1건만 고쳤다** —
"더 나은 답이 있다"는 판단을 남발하면 검색이 내놓는 것을 정답으로 만드는, 금지된 방향이 된다.

### 판정: 조건부 통과 — 다음 관문은 **크기**다

기준 1을 통과했으나 **문턱값에서 정확히 3건**이고, 그 3건은 전부 "주제가 문장으로 표현된"
부류다. 고유명사 음차는 못 푼다.

기준 3(출하 가능한 크기)이 아직 안 풀렸고, **그게 진짜 관문**이다. 여기 쓴 모델은 1.0GB이고
제품은 단일 Go 바이너리 + CGO-free + 콜드 스타트 1초다. 다음에 물을 것은 **"작은 모델로도
이 3건이 사는가"** 이고, 안 살면 Phase 1은 여기서 끝난다.

**이득의 크기를 정직하게 적어 둔다**: 25질의 중 3건을 살리면 hit@1이 최대 +12pp다.
색인 수정 두 개가 합쳐 +12pp였고 그건 모델도 디스크도 필요 없었다.

### 기준 3 실패 → **Phase 1 중단** (2026-07-27)

출하 가능한 크기로 재현되는지 물었고, **안 된다.**

`intfloat/multilingual-e5-small`(fp32 470MB)로 같은 실험을 돌렸다:

| | mpnet 1.0GB | **e5-small 470MB** |
|---|---|---|
| **언어 경계 7건 중 상위 3위** | 3건 (통과) | **1건 (폐기)** |
| `습관 만드는 법` | 1위 | **60위** |
| `판다스 10분 입문` | 1위 | **15위** |
| `기후 변화 증거` | 1위 | 1위 |
| (참고) 이미 잘 찾던 15건 | 11/15 | 14/15 |

**작은 모델이 같은 언어끼리는 오히려 낫고 언어를 건널 때만 무너진다.** 마지막 행이 그 증거다 —
같은 언어 매칭은 14/15로 큰 모델보다 좋은데, 언어 경계에서만 3건 → 1건으로 떨어진다.
크로스링구얼 정렬은 파라미터를 줄일 때 가장 먼저 잃는 능력이고, 이 실험이 그걸 그대로 보여준다.

그리고 470MB도 **출하 후보가 아니다.** 실제 후보는 int8 양자화 ONNX 118MB이고 그건 여기보다
더 나쁠 것이다. 즉 **위 표는 출하 가능성의 상한이고, 그 상한이 이미 기준 미달이다.**

#### 크기 말고도 걸리는 것

`ONNX` 런타임을 Go에서 쓰려면 CGO가 필요하다. 이 프로젝트는 **CGO-free가 SQLite 드라이버
선택까지 결정한 제약**이고(`modernc.org/sqlite`), 콜드 스타트 게이트는 1초다.
계획서 08도 "서버 CGO-free 성질을 잃는 대가"를 폐기 조건으로 적어 두었다.
크기 기준을 통과했더라도 이 관문이 남아 있었다.

#### 비용과 이득을 나란히 놓으면

| | 이득 | 비용 |
|---|---|---|
| 색인 수정 2개 (완료) | **+12pp** | 0 |
| 임베딩 (상한, 1.0GB 모델) | +12pp | 모델 파일 · 추론 시간 · CGO |

**같은 크기의 이득에 비용만 다르다.** 그리고 그 +12pp는 1.0GB 모델에서만 나오고
출하 가능한 크기에서는 +4pp로 떨어진다.

#### 결론

**Phase 1을 여기서 중단한다.** 계획서 08의 컷 순서 3번(M5 전체를 Phase A로 운영)이 발동한다.

이 스파이크가 든 비용은 하루치 실험이고, 막은 것은 2주짜리 통합이다. **폐기 기준을 실행 전에
적어 둔 것이 판정을 쉽게 만들었다** — 결과를 보고 기준을 고치고 싶은 유혹이 생기는 자리였고,
3건이 "정확히 문턱값"이었던 큰 모델 결과가 특히 그랬다.

**다시 열 조건**: 100MB 안쪽에서 크로스링구얼 정렬을 유지하는 모델이 나오거나, CGO-free
추론 경로가 생기거나, 검색 질의 로그가 쌓여 언어 경계 질의의 실제 비중이 25건 표본보다
훨씬 크다고 드러나는 경우. 셋 중 하나도 아직 아니다.
