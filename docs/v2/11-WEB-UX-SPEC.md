# 웹 UX 명세

> Push-Point v2.1 — 마지막 업데이트: 2026-07-22

이 문서는 **웹 클라이언트(`frontend/`)의 화면별 UX 명세**다.

전제 3개를 먼저 못 박는다.

1. **계약에 없는 기능은 명세하지 않는다.** 모든 필드명·파라미터·상태 코드는 [api/openapi.yaml](../../api/openapi.yaml)의 실제 이름이다. 계약에 없어서 못 하는 것은 "못 한다"고 적고 대안을 적는다(§10 계약 공백 목록).
2. **웹은 iOS와 대등한 full-feature 클라이언트다.** 유일한 차이는 "2초 공유 시트 저장"이라는 OS 기능뿐이다(`.claude/rules/frontend.md`).
3. **컨셉 규칙 R1/R2/R3이 모든 화면을 지배한다.** R1 색조는 정체성(태그 facet + 브랜드)이고 채움은 개입(fill 0/1/2) / R2 기계 데이터는 mono / R3 상태는 배지가 아니라 왼쪽 레일. R1은 2026-07-22에 개정됐다 — 정의와 확정값은 10 §1.2 · §2.1.4 · §5가 원본이고, 이 문서는 화면에서의 적용만 적는다.

**10과 11의 소유 영역 (값을 두 곳에 적지 않는다).**

| 원본 | 소유 영역 |
|---|---|
| [10-DESIGN-SYSTEM.md](10-DESIGN-SYSTEM.md) | 색·타이포·간격·반경·그림자·z 사다리, 모션 duration/easing 토큰, 컴포넌트 치수와 변형(행 높이·썸네일·인스펙터 폭 등 레이아웃 상수 §2.3), **토스트 시각 명세**(위치·동시 개수·지속·마커 §4.10), 접근성 기준(§7) |
| **11-WEB-UX-SPEC.md**(이 문서) | 화면별 레이아웃·필드 매핑·상태·반응형 동작, **키보드 단축키 표**(§1.2), **토스트를 언제 띄우는가 + 에러 코드 매핑**(§1.4), 낙관적 업데이트·폴링 규칙, 신규 의존성(§1.8), 구현 우선순위(§9), 계약 공백(§10) |

상대 문서의 소유 영역은 **값을 복제하지 않고 참조한다**(예: "지속 시간은 10 §4.10 참조"). 두 문서가 어긋나면 각 영역의 원본이 이긴다.

## 0. 화면 목록과 라우트 결정

| # | 화면 | 라우트 | 형태 | 비고 |
|---|---|---|---|---|
| 1 | 저장 Save | `/save` | 목록 위에 열리는 **컴포저**(별도 페이지 아님) | 북마클릿용 `?url=`·`?note=` 프리필 |
| 2 | 목록 List | `/` | 앱의 홈. 단일 컬럼 행 리스트 | `?tag` `?status` URL 상태 |
| 3 | 검색 Search | `/search` | 목록과 같은 행 렌더러 + 검색 툴바 | `?q` `?tag` `?from` `?to` URL 상태 |
| 4 | 태그 Tags | `/tags` | 태그 사전 관리 테이블 | 계약상 유일한 쓰기 가능 사전 |
| 5 | 상세 Detail | `/links/$id` | **인스펙터**(≥1024 우측 패널 / 미만 시트) | 딥링크 진입 시 목록 위에 열림 |
| 6 | 태그 편집 Edit | — | **상세에 통합. 별도 화면을 만들지 않는다** | 아래 결정 참조 |
| 7 | 설정 Settings | `/settings` | 단일 컬럼 폼 | API 키·테마·연결 확인·통계 |

### 결정: 편집 화면은 상세에 통합한다 (`/links/$id/edit` 폐기)

근거 4개.

- **계약이 한 번의 PATCH다.** `PATCH /api/v1/links/{id}`는 `note`와 `tags`를 함께 받고 `tags`는 **전체 교체**다. 별도 화면은 "읽기 → 편집 화면 이동 → 저장 → 돌아오기" 4단계를 만드는데, 계약상 한 번의 요청이면 끝난다.
- **응답이 곧 상세다.** PATCH의 200 응답은 `LinkDetail` 전체다. 편집 결과를 보여줄 화면이 이미 상세 화면이므로 화면을 분리하면 같은 렌더러를 두 번 만든다.
- **낙관적 업데이트와 상충한다.** 태그 토글은 즉시 반영이 원칙(§8)인데, 화면을 옮겨 "저장 버튼"을 누르는 모델은 낙관적 업데이트를 쓸 자리를 없앤다.
- **iOS와의 정합.** iOS는 `.sheet` + detents로 상세를 열고 그 안에서 편집한다. 웹만 라우트를 하나 더 갖는 것은 §7 "같은 정보 계층" 원칙 위반이다.

**마이그레이션**: 기존 `/links/$id/edit` 라우트는 삭제하고 `/links/$id`로 리다이렉트한다(북마크 호환). 편집 상태는 라우트가 아니라 인스펙터 내부 포커스(`E`/`N` 단축키)로 표현한다.

### 결정: 저장은 페이지가 아니라 컴포저다

목록 최상단에 행이 즉시 생기는 것(시그니처 S2)이 저장 UX의 전부다. 저장 전용 페이지로 이동하면 **저장 결과가 보이지 않는 화면에서 저장**하게 되어 시그니처가 죽는다. 그래서 `/save`는 "목록 + 컴포저가 열리고 URL 필드에 포커스된 상태"로 렌더한다. 상단 바의 `저장` 링크와 `S` 단축키가 같은 상태를 연다.

## 1. 전역 요소

### 1.1 내비게이션: 상단 바 확정, 좌측 사이드바 없음

```
+----------------------------------------------------------------------+
| Push-Point   목록  검색  태그  설정        [ 저장 ]  [테마]  [?]      |  sticky glass 헤더
+----------------------------------------------------------------------+
```

(헤더·툴바 높이 등 치수는 10 §2.3 레이아웃 상수가 원본이다. 아래 다이어그램의 숫자 주석도 전부 10 §2.3을 따른다.)

- 화면이 5개(목록/검색/태그/설정 + 상세는 오버레이)뿐이고 사용자가 1명이다. 사이드바는 데스크톱 폭을 상시 점유하면서 모바일에서는 버려지는 중복 내비게이션이다.
- `저장`만 액센트 primary 버튼, 나머지 4개는 텍스트 링크(활성 항목은 weight 500 + `fg-1`). 브랜드 solid를 쓰는 4곳(10 §2.1.4) 중 상단 바에 해당하는 것은 primary 버튼 하나뿐이다.
- `Cmd/Ctrl+K` 커맨드 팔레트가 내비게이션·검색·최근 태그 이동을 겸한다. 팔레트가 있으므로 상단 바에 드롭다운을 만들지 않는다.
- `< 560`: 텍스트 내비 4개가 아이콘 4개로 축약되지 않는다 — **그대로 두고 가로 스크롤도 만들지 않는다**. 대신 `Push-Point` 로고를 숨기고 `저장`을 아이콘 버튼(+)으로 줄인다. 하단 탭바를 만들지 않는 이유: 하단 탭바는 iOS의 관용이고, 웹에서는 주소창/시트와 충돌한다.

### 1.2 키보드 단축키 표 — 유일 원본

**이 표가 앱의 키보드 계약 전부다.** 10 §7.3은 접근성 요구(roving tabindex, 포커스 노출 규칙, `aria-live`)만 담고 키 배정은 이 표를 참조한다. 입력 필드 안에서는 단일 문자 단축키가 전부 비활성이다(`Esc`·`Cmd/Ctrl+Enter` 제외).

| 키 | 범위 | 동작 |
|---|---|---|
| `Cmd/Ctrl+K` | 전역 | 커맨드 팔레트 열기(이동 + 검색 + 태그 점프) |
| `/` | 목록·검색 | 검색 입력 포커스(목록에서는 `/search`로 이동하며 포커스) |
| `S` | 전역 | 저장 컴포저 열고 URL 필드 포커스 |
| `Cmd/Ctrl+V` | 입력 밖 | 클립보드가 `http(s)://`로 시작하면 **즉시 저장**(§1.5 낙관적 저장, 실행취소 토스트) |
| `J` / `↓` | 목록·검색 | 다음 행으로 커서 이동(가상 스크롤 위치 동기) |
| `K` / `↑` | 목록·검색 | 이전 행으로 커서 이동 |
| `Enter` | 목록·검색 | 커서 행의 인스펙터 열기 |
| `O` | 행 커서·인스펙터 | `url`을 새 탭으로 열기 — **원문 열기는 이 키 하나뿐이다** |
| `E` | 행 커서·인스펙터 | 인스펙터를 열고 **태그 입력**에 포커스 |
| `N` | 행 커서·인스펙터 | 인스펙터를 열고 **메모 입력**에 포커스 |
| `R` | 행 커서·인스펙터 | `status === 'failed'`일 때만 재시도(`POST /links/{id}/retry`) |
| `Backspace` / `Delete` | 행 커서·인스펙터 | 링크 소프트 삭제(`DELETE /links/{id}`) + 실행취소 토스트 |
| `Cmd/Ctrl+Enter` | **저장 폼 안**(컴포저 URL·메모, 인스펙터 메모, 태그 편집 행) | 그 폼을 **즉시 제출/저장**(blur·버튼 클릭 대기 없이) |
| `Esc` | 전역 | 팔레트 → 컴포저 → 인스펙터 → 검색어 순으로 **하나씩** 닫기/비우기 |
| `?` | 전역 | 이 표를 그대로 띄우는 단축키 오버레이 |

- **`Cmd/Ctrl+Enter`는 저장 전용이다.** 폼 밖에서는 아무 동작도 하지 않는다 — 원문 열기에 겸용하면 "메모를 쓰다 저장하려다 새 탭이 열리는" 오작동이 생긴다.
- **`Cmd/Ctrl+V` 즉시 저장의 구현 수단**: `document` 레벨 `paste` 이벤트의 `event.clipboardData.getData('text')`**만** 읽는다. `navigator.clipboard.readText()`는 **금지** — Safari가 붙여넣기 확인 UI를 띄우고 Firefox는 거부해서 §1.5의 "입력 지연 0" 전제가 깨진다. 키 조합을 직접 가로채는 `keydown` 핸들러도 쓰지 않는다(브라우저가 클립보드를 주지 않는다).
- **다중 선택(`X`, `Shift+↑↓`)과 테마 순환(`T`)은 이 표에 없다.** 전자는 계약에 배치 엔드포인트가 없어 N개 선택이 N번 요청이 되므로 MVP 제외(§10-3), 후자는 설정 화면의 3-state 세그먼트(§8)가 유일 경로다.
- **삭제 확인 정책은 하나다.** 링크 삭제는 **확인 다이얼로그 없이 즉시 실행 + 실행취소 토스트**(복원 수단이 있다, §1.5). 확인 다이얼로그(`AlertDialog`)는 **태그 사전 삭제 한 곳에만** 쓴다 — CASCADE라 되돌릴 수 없기 때문이다(§5-4).
- 모든 단축키는 `?` 오버레이와 이 표가 유일한 원본이다. 툴팁에 단축키를 중복 표기하지 않는다.

### 1.3 표시 폴백 규칙 (전 화면 공통 — iOS와 동일)

| 상황(계약 표현) | 표시 |
|---|---|
| `title === ''` | `domain` → 그것도 비면 `url` |
| `thumb_url === null` | `domain[0].toUpperCase()` + `bg-hover` 배경. **색상 해시 금지** |
| `description === ''` | 인스펙터에서 슬롯 자체를 숨김(빈 줄 금지) |
| `author`/`lang`/`error === ''` | 해당 **행 전체를 숨김**(라벨만 남기지 않는다) |
| `confidence === null` (= `source: 'manual'`) | 신뢰도 슬롯 비움. `0`으로 표기 금지 |
| `jobs.tag`/`jobs.thumb` **필드 부재** | "아직 없음"(`fg-3`, `—`). `failed`와 **다른 상태**로 렌더 |
| `jobs.thumb === 'failed'` + `status === 'done'` | **정상 조합.** 링크 실패로 표시하지 않는다 |
| `rank === null` (검색 `mode: 'like'`) | 랭크 슬롯 비움 |
| `content_type === 'video'` | 썸네일 우하단 재생 아이콘(16px — 10 §1.3의 두 사이즈 중 작은 쪽). 나머지 3종(`article`/`post`/`other`)은 **무표시** |

### 1.4 토스트를 언제 띄우는가 + 에러 코드 매핑

> **시각 명세는 여기 없다.** 위치·동시 표시 개수·지속 시간·마커 색·진입/퇴장 전이는 전부 **10 §4.10 Toast**가 원본이다. 이 절은 "어떤 사건에 어떤 변형을 띄우는가"만 정한다.

1. **언제 띄우는가**: 결과가 **현재 화면 밖**에서 일어났을 때만. 화면에 즉시 반영이 보이는 조작(태그 토글, 메모 저장, 필터 적용)에는 토스트를 띄우지 않는다.
2. **구성**: 문장 1줄 + 액션 최대 1개. 아이콘 없음, 이모지 없음.
3. **사건 → 변형 매핑**:

| 사건 | 변형(10 §4.10) | 문구 · 액션 |
|---|---|---|
| 저장 중복(`200 duplicate:true`) | `warn` | "이미 저장한 링크입니다." · `열기` → `/links/{id}` |
| 링크 삭제(`204`) | `undo` | "삭제했습니다." · `되돌리기 — 다시 수집됩니다`(§1.5) |
| `Cmd/Ctrl+V` 즉시 저장 성공 | `undo` | "저장했습니다." · `되돌리기`(= `DELETE`) |
| 태그 사전 삭제(`204`) | `success` | "`개발`을 삭제했습니다." · 액션 없음(복원 불가 — §5-5) |
| 서버 오류(`500 internal` — 계약에 선언됨) | `error` | `error.message` · `다시 시도` |
| 낙관적 뮤테이션 롤백(`4xx`) | `error` | `error.message` · 액션 없음(입력이 그대로 남는다) |

4. **에러 코드 → UI 매핑**(계약의 4개가 전부):

| `error.code` | HTTP | UI |
|---|---|---|
| `unauthorized` | 401 | 토스트 아님. **상단 고정 배너**("API 키가 필요합니다 · 설정 열기") + 해당 쿼리 재시도 중단 |
| `invalid_input` | 400 | 입력 필드 **인라인** 메시지(`error.message` 그대로). 토스트 금지 |
| `not_found` | 404 | 인스펙터를 "삭제되었거나 없는 링크입니다" 상태로 교체 + 목록 캐시에서 해당 행 제거. 토스트 금지 |
| `internal` | 500 | `error` 토스트 + `다시 시도` 액션 1개 |
| 네트워크 실패(응답 없음) | — | 토스트 금지. §1.6 오프라인 바로 처리 |

**`500`은 계약에 선언되어 있다** — `api/openapi.yaml`의 각 path가 `InternalError` 응답을 갖고 `Error.code`의 `internal`과 1:1이다. 위 표의 상태 코드는 전부 계약의 실제 이름이며(전제 1), 클라이언트는 `error.code`로 분기하고 상태 코드는 로깅·진단에만 쓴다.

5. **성공 토스트에는 액센트를 쓰지 않는다.** 성공은 무채색이다 — 브랜드 solid가 붙는 자리는 10 §2.1.4의 4곳으로 고정돼 있고 토스트는 거기 없다(R1). 색을 쓰는 변형은 `warn`·`error` 둘뿐이며, 색 단독으로 의미를 전달하지 않고 항상 문장이 같은 정보를 반복한다.

### 1.5 저장 플로우의 낙관적 업데이트

계약상 저장은 `POST /api/v1/links` **201(신규) / 200(`duplicate: true`)** 두 갈래다. 이 분기를 UI가 그대로 표현한다.

```
제출 t=0ms      낙관적 행을 목록 최상단에 삽입
                { id: -tmp, url, domain(클라이언트 파싱), title:'', description:'',
                  content_type:'other', thumb_url:null, status:'pending',
                  tags:[], note, created_at: now }
                → 컴포저 즉시 비우고 닫힘. 입력 지연 0.

201 응답        temp id → 응답의 { id, status, created_at }로 치환 후
                GET /api/v1/links/{id} 1회로 행을 실값으로 교체
                (전체 목록 invalidate 금지 — 스크롤 위치와 다른 행이 흔들린다)

200 응답        duplicate:true → 낙관적 행 제거, 경고 토스트
                "이미 저장한 링크입니다." [열기] → /links/{id} 인스펙터

4xx/5xx·네트워크 실패
                낙관적 행 제거 + 컴포저를 입력값 그대로 다시 열고 인라인 에러
```

**진행 상태 추적은 폴링이 유일한 수단이다.** 계약에 SSE/WebSocket이 없다(§10-1). 규칙:

- 대상: `status ∈ {pending, scraping, tagging}`이면서 **뷰포트 안에 있는** 행만.
- 주기: `GET /api/v1/links/{id}` 1초 간격 × 10회 → 이후 3초 간격 × 40회 → 중단(총 약 2분). `done`/`failed`면 즉시 중단.
- `document.visibilityState === 'hidden'`이면 정지, 복귀 시 즉시 1회 실행.
- 폴링 응답은 **그 행만** 교체한다. 목록 쿼리 전체를 무효화하지 않는다.

다른 낙관적 뮤테이션:

| 조작 | 엔드포인트 | 낙관 반영 | 롤백 |
|---|---|---|---|
| 태그 토글/추가/삭제 | `PATCH /links/{id}` `{tags:[name…]}` (전체 교체) | 칩 즉시 추가/제거, 추가분은 `source:'manual'`·`confidence:null`로 표시 | 이전 `tags` 배열 복원 + 에러 토스트 |
| 메모 저장 | `PATCH /links/{id}` `{note}` | 즉시 텍스트 반영 | 이전 `note` 복원 |
| 삭제 | `DELETE /links/{id}` | 행 즉시 제거(§1.7 행 제거 모션) | 행 복원 |
| 재시도 | `POST /links/{id}/retry` | 레일을 즉시 진행(pulse)로, `status:'pending'` | `failed`로 복원 |

**삭제 실행취소의 한계를 명시한다.** 계약에 복원 엔드포인트가 없다. 대신 `POST /api/v1/links`가 "소프트 삭제된 URL 재저장 = 같은 행 복원(pending 복귀, note 교체, scrape 재-enqueue)"이므로 실행취소는 **같은 `url`과 `note`로 재-POST**로 구현한다. 결과적으로 링크는 살아나지만 **`status`가 `pending`으로 돌아가고 스크랩이 다시 돈다**. 토스트 문구가 이 사실을 감추지 않는다 → "삭제했습니다. [되돌리기 — 다시 수집됩니다]".

### 1.6 오프라인·에러 전역 상태

- **웹에 오프라인 저장 큐를 만들지 않는다.** 그것은 iOS Share Extension의 App Group 큐가 담당하는 역할이고, 웹에서 흉내 내면 두 클라이언트가 서로 다른 중복 규칙을 갖게 된다.
- `navigator.onLine === false` 또는 요청이 네트워크 레벨에서 실패하면 상단 바 아래에 **오프라인 바**(무채색, 아이콘 없음)를 고정한다: "서버에 연결할 수 없습니다. 저장·수정이 비활성화됩니다."
- 오프라인 동안: 모든 쓰기 버튼 `disabled` + `aria-disabled`. **읽기는 막지 않는다** — TanStack Query 캐시에 남은 목록/상세는 계속 보이고, 각 행은 그대로 유지된다(회색 처리하지 않는다).
- 온라인 복귀 시 현재 화면의 쿼리만 재검증하고 토스트는 띄우지 않는다(사용자가 이미 바가 사라지는 것을 본다).

### 1.7 로딩·행 전이 규칙 (전 화면 공통)

- **200ms 규칙**: 요청이 200ms 안에 끝나면 스켈레톤을 렌더하지 않는다. 로컬 서버 p99 < 50ms이므로 대부분의 요청이 여기 해당한다.
- 용도별 분리: 리스트 첫 진입 = **스켈레톤 행**(최종 치수 그대로) / 단일 액션 = **버튼 내 스피너** / 스크랩 대기 = **레일 펄스**(별도 스피너 금지).
- `isPending` 동안 빈 상태를 절대 렌더하지 않는다.
- **CLS 0**: 행 높이·썸네일·인스펙터 폭을 전부 사전 예약한다. 실제 치수는 10 §2.3 레이아웃 상수가 원본이고 이 문서는 그 값을 복제하지 않는다.

**행 삽입/제거 모션은 `transform`/`opacity`만 쓴다** (10 §6.1의 "`top`/`height` 애니메이션 금지"). 목록·검색·태그 화면이 전부 이 규칙을 공유한다.

| 사건 | 구현 |
|---|---|
| 행 삽입(낙관적 저장 S2) | 새 행은 `opacity 0→1` + `translateY(-4px→0)` `--dur-2`(180ms) — 10 §6.1 "저장 직후 행 삽입·채워짐(S2)" 행이 원본이다. **아래 행들은 FLIP `translateY`** `--dur-flip`(220ms) — 컨테이너 높이는 첫 프레임에 이미 최종값이다 |
| 행 제거(삭제) | 대상 행을 **`position: absolute` 스냅샷**으로 띄워 문서 흐름에서 즉시 빼고 `opacity 1→0` + `scaleY(1→.96)` `--dur-out`(120ms), 아래 행들은 같은 프레임에 FLIP `translateY` `--dur-flip`(220ms) |
| 인라인 편집 펼침 | `grid-template-rows: 0fr → 1fr` `--dur-2`(180ms) + 내용 `opacity`. `height`를 직접 애니메이션하지 않는다. **`grid-template-rows` 보간은 10 §6.1이 등재한 승인된 예외이며 적용 대상은 태그 사전의 편집 행 하나뿐이다** |

- 가상 스크롤(§3-6) 구간에서는 FLIP 대상이 **뷰포트 안 행으로 한정**된다. 화면 밖 행에 transform을 걸지 않는다.
- `--dur-flip`(220ms)과 `--dur-close`(200ms)는 10 §2.6의 duration 토큰이다. 이 문서에 나오는 모든 시간 값은 그 허용 집합(120/160/180/200/220/260ms + 레일 펄스 2400ms + 토스트 지속) 안에 있고, **위 세 전이는 전부 10 §6.1의 사용처 표(6곳)에 등재되어 있다** — 그 표에 없는 모션을 이 문서가 새로 만들지 않는다.

### 1.8 이 명세가 요구하는 신규 의존성

현재 `frontend/package.json`에는 React 19 / TanStack Router·Query / Tailwind v4 / openapi-fetch / lucide-react / zod만 있다. 이 명세를 구현하려면 아래 패키지가 **추가로** 필요하다. 이 표가 도입 목록의 원본이고, 여기 없는 UI 라이브러리는 도입하지 않는다.

| 패키지 | 쓰이는 곳 | 도입 시점 |
|---|---|---|
| `@radix-ui/react-dialog` | 인스펙터/시트(§6-6), 커맨드 팔레트, `?` 단축키 오버레이 | P0 |
| `@radix-ui/react-popover` | 검색 기간·태그 필터(§4-2), **태그 콤보박스의 컨테이너**(§6-4) | P0 |
| `@radix-ui/react-select` | 목록 상태 필터 드롭다운(§3-4), **태그 관리 화면의 facet 4지선다**(§5-4) | P0 |
| `@radix-ui/react-visually-hidden` | 아이콘 버튼 라벨, `aria-live` 상태 문장 | P0 |
| `@radix-ui/react-alert-dialog` | **태그 사전 삭제 확인 한 곳**(§5-4) | P1 |
| `@radix-ui/react-tooltip` | 툴바·행 액션 툴팁 | P1 |
| `@tanstack/react-virtual` | 렌더 행 200개 초과 시 가상 스크롤(§3-6) | P1(측정 후) |

**콤보박스와 커맨드 팔레트는 직접 만든다.** Radix에는 Combobox 프리미티브가 **없고**(제공 목록은 10 §4.11), `cmdk` 같은 별도 라이브러리도 도입하지 않는다. 둘 다 `Popover`(또는 `Dialog`) + 자체 입력 + 필터 리스트로 ARIA combobox 패턴(`role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`, 리스트는 `role="listbox"`/`role="option"`)을 직접 구현한다. 리스트 필터는 대소문자 무시 부분 문자열 매칭 1개뿐이다 — 퍼지 매칭 라이브러리를 끌어오지 않는다.

토스트도 라이브러리 없이 직접 만든다 — 문장 1줄 + 액션 1개짜리 컴포넌트에 의존성을 붙일 이유가 없다. 시각 명세는 10 §4.10, 접근성 역할(`role="status"` / `role="alert"`, `aria-live` 영역 1개)은 10 §7이 원본이고 이 문서는 §1.4에서 "언제 어떤 변형을 띄우는가"만 정한다.

## 2. 화면 1 — 저장 (Save)

**(1) 목적** — URL 하나를 최소 입력으로 던져 넣고, 결과가 목록 최상단에서 채워지는 것을 보게 한다.

**(2) 레이아웃**

```
+----------------------------------------------------------------------+
| Push-Point   목록  검색  태그  설정        [ 저장 ]  [테마]  [?]      |
+----------------------------------------------------------------------+
|  +----------------------------------------------------------------+  |  컴포저 (목록 위 인라인)
|  | URL   https://…                                    [ 저장 ⏎ ]  |  |  --radius-panel, --sh-panel
|  | 메모  (선택) 왜 저장했는지                                     |  |
|  +----------------------------------------------------------------+  |
|                                                                      |
| ▎[■] ────────────    ░░░░░░░░░░                    ░░░ ░░░           |  ← 방금 만든 낙관적 행
| ▎    example.com · 방금                                              |     (스켈레톤 = S2 "채워지는 행")
| ──────────────────────────────────────────────────────────────────── |
| ▎[::] 이전에 저장한 링크 제목                       #개발 #영상      |
+----------------------------------------------------------------------+
```

**(3) API 필드 매핑**

| UI | 계약 |
|---|---|
| URL 입력 | `LinkInput.url` (required) |
| 메모 입력 | `LinkInput.note` (optional) |
| 제출 결과(신규) | `201 { id, status, created_at }` |
| 제출 결과(중복) | `200 { id, duplicate: true }` |
| 낙관적 행의 `domain` | 클라이언트가 `new URL(url).hostname`으로 파싱(서버 응답 오면 서버 값이 승) |
| 인라인 에러 | `400 error.message` 그대로 |

**(4) 상호작용**

- `S`로 열림 → URL 필드 자동 포커스. `Enter` 제출, `Cmd/Ctrl+Enter`는 메모 필드에 있어도 즉시 제출, `Esc` 닫기(입력값은 세션 동안 보존).
- URL 필드에 붙여넣기만 해도 제출 버튼이 활성. 클라이언트 검증은 `http(s)://` 접두사 1개뿐 — 나머지 판정은 서버(`invalid_input`)에 맡긴다.
- 입력 밖에서 `Cmd/Ctrl+V` → 클립보드가 URL이면 컴포저를 열지 않고 **즉시 저장**하고, 토스트에 `되돌리기`(= `DELETE`)를 단다. 클립보드는 `document` 레벨 `paste` 이벤트의 `clipboardData`로만 읽는다(§1.2 각주 — `navigator.clipboard.readText()` 금지).
- 메모 필드는 `Tab`으로만 도달. 저장의 기본 경로는 URL + Enter 2동작이다.
- 북마클릿 진입 `/save?url=…&note=…`는 필드를 프리필하되 **자동 제출하지 않는다**(오폭 방지).

**(5) 상태별**

| 상태 | 표현 |
|---|---|
| 로딩(제출 중) | 없음. 낙관적 행이 이미 삽입됐으므로 버튼 스피너도 띄우지 않는다 |
| 빈 상태 | 해당 없음(컴포저는 항상 입력 가능) |
| 에러 400 | URL 필드 아래 인라인 `danger` 1줄. 컴포저 유지, 입력값 유지 |
| 중복 200 | 경고 토스트 + `열기`. 컴포저는 닫힘(중복은 실패가 아니다) |
| 오프라인 | 컴포저 열리지만 제출 버튼 비활성 + "서버에 연결할 수 없습니다" 인라인 |
| 키 없음(401) | 컴포저 대신 "설정에서 API 키를 입력하세요 · [설정 열기]" |

**(6) 반응형**

| 폭 | 변화 |
|---|---|
| `< 560` | 컴포저가 화면 상단 고정 시트. URL 입력은 터치 타깃 최소 치수(10 §7.5), 저장 버튼은 입력 아래 전폭 |
| `560~1023` | 목록 상단 인라인 카드. 저장 버튼은 입력 우측 인라인 |
| `≥ 1024` | 동일 + 인스펙터가 열려 있어도 컴포저는 목록 컬럼 폭에만 놓인다 |

**(7) 모션** — 컴포저 진입·퇴장은 **10 §6.1의 "커맨드 팔레트·컴포저" 행 그대로**이며 이 문서는 속성·시간을 복제하지 않는다(모션 소유권은 10에 있다 — 10 서두의 소유 경계표). 낙관적 행 삽입도 **§1.7 "행 삽입" 규칙 그대로**이고, 그 규칙 자체가 10 §6.1의 "저장 직후 행 삽입·채워짐(S2)" 행에 등재되어 있다. **높이를 애니메이션하지 않는다**(10 §6.1).

**(8) iOS 차이** — 공유 시트 1탭 저장이 기본 경로이고 앱 내 URL 입력 폼은 보조 수단이므로, 컴포저는 `.sheet`의 작은 detent로만 존재한다.

| 상태 레일 | `status` | `done`→투명 / `pending`·`scraping`·`tagging`→`rail-progress` 펄스 / `failed`→`danger` 실선. 토큰의 라이트·다크 값은 10 §2.1.2, 펄스 규격은 10 §4.7 |
| 썸네일 | `thumb_url` | `null`이면 `domain` 첫 글자. `loading="lazy" decoding="async"`, 다크에서 `brightness(.92)` |
| 재생 아이콘 | `content_type` | `'video'`만 표시 |
| 제목 | `title` | 빈 문자열이면 `domain` → `url` |
| 도메인 | `domain` | mono, `fg-3` |
| 시각 | `created_at` | epoch초 → 상대 표기(방금/N분 전/N시간 전/어제/M월 D일). mono·`tabular-nums`, `title` 속성에 절대 시각 |
| 태그 칩 | `tags[]` (`LinkTag`) | 정렬: `source==='manual'` 우선 → `confidence` desc → `name`. 색은 10 §5.2 `chipStyle`이 정한다 — **행 칩은 `role: 'readonly'`, `manual`은 fill 1(그 태그의 facet tint), 그 외는 fill 0** |
| 칩의 facet | **`LinkTag`에 없다** | `GET /api/v1/tags` 캐시에서 `Map<tagId, facet>`으로 해석한다. **캐시 미스는 추측하지 않고 `neutral`**(10 §5.2 · §9 계약 정합) |
| 메모 존재 표시 | `note !== ''` | 아이콘 1개만. 내용은 인스펙터 |
| 원문 열기 | `url` | hover 액션 + `O` |
| 더 불러오기 | `next_cursor` | `null`이면 끝. IntersectionObserver 자동 로드 |
| 태그 필터 | 쿼리 `tag` | `?tag=` URL 상태와 1:1 |
| 상태 필터 | 쿼리 `status` | `LinkStatus` 5값 + 전체 |
| 페이지 크기 | 쿼리 `limit` | 고정 50(계약 최대 100, 기본 20) |

**목록에 표시하지 않는 것**: `description`(인스펙터로 이동 — 밀도 기여가 가장 큼), `confidence`, `note` 본문.

**(4) 상호작용**

- 행 클릭 = 인스펙터 열기. **원문 열기가 아니다**(원문은 `열기` 버튼/`O`/`Cmd+클릭`). 제목만 `<a href={url}>`로 두고 나머지 영역이 인스펙터 트리거다.
- hover/포커스에서만 우측 액션 노출: `열기` / `…`(재시도·삭제). `@media (hover: none)`에서는 상시 표시.
- `J`/`K` 커서 이동 시 행에 `scroll-margin`을 두어 sticky 툴바에 가리지 않게 한다.
- 태그 칩 클릭 = `?tag` 토글(단일 값 — 계약이 `tag` 파라미터 1개다). 칩 우클릭 메뉴 없음.
- **칩 바(필터 바)의 칩은 컨트롤이고 행 안의 칩은 표시 전용이다.** 필터 칩만 `--line-control` 보더를 갖고(WCAG 1.4.11 컨트롤 경계), 행·인스펙터 칩은 `readonly`라 보더가 없다(10 §4.3 · §7.1). 선택된 필터 칩은 그 태그 facet의 solid 채움(fill 2)이며 hue는 바뀌지 않는다.
- **선택된 행 안에서는 `fill 1` 칩만 fill 0으로 내려간다** — 행 배경(`--bg-selected`)과 `craft` tint가 같은 값이기 때문이다(10 §4.3). **현재 `?tag`와 일치하는 칩은 선택된 행 안에서도 fill 2를 유지한다**(분기 순서는 10 §5.2가 원본 — `selected`가 가장 먼저 평가된다). `chipStyle`의 `onSelectedRow` 인자는 `manual` 분기에서만 쓰인다.
- 상태 드롭다운(`@radix-ui/react-select`, §1.8)에서 `failed`를 고르는 것이 실패 링크 정리 동선이다.
- 스와이프: `@media (hover:none)`에서 행 좌측 스와이프 → 삭제, 우측 스와이프 → 재시도(`failed`만). 60px 이상 끌면 확정, 미만은 스프링 없이 `--dur-out`(120ms) 복귀.

**(5) 상태별**

| 상태 | 표현 |
|---|---|
| 로딩 | 스켈레톤 행 8개(행 높이 그대로 고정 — 10 §2.3). 200ms 안에 오면 미표시 |
| 빈 상태(필터 없음) | "저장된 링크가 없습니다." + `링크 저장하기` 버튼(컴포저 열기). 일러스트·이모지 없음 |
| 빈 상태(필터 있음) | "`#개발` + `실패` 조건에 맞는 링크가 없습니다." + `필터 해제` |
| 다음 페이지 로딩 | 하단에 스켈레톤 2행. "더 보기" 버튼은 IntersectionObserver 실패 시 폴백으로만 |
| 에러 | 목록 자리에 무채색 블록 + `error.message` + `다시 시도`. 이미 로드된 페이지는 유지 |
| 오프라인 | 캐시된 행 유지 + 상단 오프라인 바. 무한 스크롤 중단 |

**(6) 반응형**

| 폭 | 행 치수 | 칩 | 인스펙터 |
|---|---|---|---|
| `< 560` | 모바일 치수(10 §2.3) | 0개(태그 아이콘 + 개수) | 풀스크린 시트 |
| `560~1023` | 데스크톱 치수(10 §2.3) | 2개 | bottom sheet `85dvh` |
| `≥ 1024` | 동일 | 3개 | 우측 고정 패널(폭 10 §2.3) |
| `≥ 1280` | 동일 | 3개 | 페이지 최대 폭 + 데스크톱 거터 적용(10 §2.3) |

칩 개수는 **컨테이너 쿼리**로 결정한다(인스펙터 개폐에 따라 행의 실제 가용 폭이 달라지므로 뷰포트 기준은 틀린다). 렌더 행이 200개를 넘으면 `@tanstack/react-virtual`로 전환(행 높이 고정이라 비용 거의 0).

**(7) 모션** — 행 hover는 진입 0ms / 이탈 `--dur-out`(120ms). 행 삽입·제거는 §1.7 표 그대로(**둘 다 `transform`/`opacity`만**, 높이 애니메이션 없음). 스켈레톤→실값 crossfade `--dur-2`(180ms), 썸네일 `opacity 0→1` `--dur-3`(260ms). 진행 레일 펄스 2400ms(앱 내 유일한 무한 루프). **stagger 진입·스크롤 리빌·행 상승 금지.**

**(8) iOS 차이** — `List` + `.swipeActions`가 hover 액션을 대체하고, 헤더는 `.navigationTitle(.large)`이라 툴바 칩 바가 large title 아래로 붙는다.

## 4. 화면 3 — 검색 (Search)

**(1) 목적** — 기억나는 단어 하나로 아카이브를 좁히고, 지금 어떤 경로(FTS5 / LIKE)로 찾았는지 숨기지 않는다.

**(2) 레이아웃**

```
+--------------------------------------------------------------------------------+
| [🔍 검색어                                        ] [기간 ▾]  [태그 ▾]  [지우기]|  툴바
| FTS5 · bm25 정렬 · 불러온 20건                                                 |  결과 메타 (mono, fg-3)
+-----------------------------------------------------+--------------------------+
| ▎[::] Kubernetes 네트워킹 정리              #개발     |  인스펙터                |
| ▎     kubernetes.io · 3시간 전                       |                          |
| ─────────────────────────────────────────────────── |                          |
| ▎[::] k8s 트러블슈팅                        #개발     |                          |
+-----------------------------------------------------+--------------------------+
```

행 렌더러는 목록과 **완전히 동일한 컴포넌트**다. 검색 결과라고 다른 카드를 쓰지 않는다(정보 위계 동일 원칙).

**(3) API 필드 매핑** — `GET /api/v1/search` → `SearchPage`

| UI | 필드/파라미터 |
|---|---|
| 검색 입력 | 쿼리 `q` (required, `minLength: 1`) |
| 태그 드롭다운 | 쿼리 `tag` |
| 기간 드롭다운 | 쿼리 `from` / `to` (epoch초. 프리셋: 전체 / 최근 7일 / 30일 / 올해) |
| 페이지 | 쿼리 `cursor`, `limit`, 응답 `next_cursor` |
| 결과 메타 라벨 | 응답 `mode` — `fts` → "FTS5 · bm25 정렬" / `like` → "LIKE 폴백 · 최신순" |
| 결과 메타 건수 | **응답 필드가 아니다.** 클라이언트가 지금까지 받은 페이지의 `links[]` 길이 누계이며 라벨을 반드시 "불러온 N건"으로 쓴다 |
| 결과 행 | `links[]` (`SearchResult` = `Link` + `rank`) |
| 랭크 | `rank` — **목록 행에 표시하지 않고 인스펙터 진단 슬롯에만** mono 소수 2자리. `null`(like 모드)이면 슬롯 비움 |

**계약 사실 3개를 UI가 반영한다.**
- **총 건수 필드가 없다.** `SearchPage`는 `mode`/`links`/`next_cursor`뿐이고 `LinkPage`도 `links`/`next_cursor`뿐이다(커서 페이지네이션이라 서버가 총계를 세지 않는다). 그래서 "24건" 같은 **전체 결과 수를 절대 표시하지 않는다** — 표시하는 숫자는 "불러온 N건"뿐이고, 이 값은 `next_cursor !== null`인 동안 계속 늘어난다. 목록 화면의 빈 상태·필터 문구도 같은 이유로 건수를 쓰지 않는다(§10-7).
- 검색에는 **`status` 파라미터가 없다.** 그래서 검색 툴바에 상태 필터를 두지 않는다(목록 전용).
- 목록 커서와 검색 커서는 **형식이 호환되지 않는다.** `q`/`tag`/`from`/`to`가 바뀌면 커서를 반드시 버리고 첫 페이지부터 다시 요청한다(재사용 시 400).

**(4) 상호작용**

- **Enter 불필요.** 입력 디바운스 120ms → `navigate({ search, replace: true })`로 `?q` 동기화(히스토리 오염 방지).
- 3자 미만이어도 에러가 아니다(계약: LIKE 폴백). "3자 이상 입력하세요" 같은 안내를 띄우지 않고 그냥 검색한다. 대신 결과 메타에 `LIKE 폴백 · 최신순`을 표시해 정렬 기준이 다르다는 사실만 알린다.
- `/`로 포커스, `Esc`는 1) 검색어 비우기 → 2) `/`로 이동 순서.
- `J`/`K`/`Enter`/`O` 등 행 단축키는 목록과 동일.
- 매칭 하이라이트는 **하지 않는다.** FTS5 trigram 매칭 구간을 클라이언트가 정확히 복원할 수 없어 잘못된 하이라이트를 만든다(§10-4).

**(5) 상태별**

| 상태 | 표현 |
|---|---|
| `q === ''` | 결과 영역을 비우고 "검색어를 입력하세요." 한 줄. 최근 검색어 저장 안 함 |
| 로딩 | 스켈레톤 행 5개. 입력은 절대 잠그지 않는다(타이핑 중 재요청은 이전 요청 abort) |
| 빈 결과 | "`쿠버네티스`에 해당하는 링크가 없습니다." + 활성 필터가 있으면 `필터 해제` |
| 에러 400(커서 형식 등) | 커서를 버리고 첫 페이지 자동 재요청 1회, 실패 시 에러 블록 |
| 오프라인 | 입력 비활성 + 마지막 결과 유지 |

**(6) 반응형** — `< 560`: 기간·태그 드롭다운이 입력 아래 한 줄로 내려가고 결과 메타는 그 아래. `≥ 1024`: 입력 최대 폭 `--w-search-input`(값은 10 §2.3), 좌측 정렬(중앙 정렬 금지 — 목록과 좌측 기준선을 공유해야 행이 흔들리지 않는다).

**(7) 모션** — 결과 교체는 **fade 없음**(입력마다 깜빡이면 타이핑이 방해된다). 이전 결과를 그대로 두고 새 결과로 치환하며, 로딩 중에는 결과 메타 줄의 opacity만 `.55`로 낮춘다. 필터 칩 추가/제거만 `--dur-2`(180ms).

**(8) iOS 차이** — `.searchable`이 검색 입력을 대체한다. 나머지 툴바 요소는 **한 축씩 나눠 배치한다** — `.searchScopes`는 세그먼티드 컨트롤 한 줄이라 값이 3~5개일 때만 성립하는데, 태그는 사전 30~50개(§5-1)라 두 축을 한 scope bar에 넣을 수 없다.

| 웹 요소 | iOS 배치 |
|---|---|
| 기간 프리셋 4개(전체 / 최근 7일 / 30일 / 올해) | `.searchScopes` — 값이 정확히 4개라 세그먼티드 컨트롤에 맞는다 |
| 태그 필터(사전 30~50개) | 툴바 `Menu` **단일 선택 피커**(계약의 `tag` 파라미터가 1개다). scope bar에 넣지 않는다 |
| 결과 메타(`mode` + "불러온 N건") | 결과 리스트의 **첫 섹션 헤더**로 분리. `.font(.footnote.monospaced())` + `fg-3` 대응 색 |
| `지우기` | `.searchable`의 시스템 clear 버튼이 대신한다(별도 버튼 없음) |

검색 화면은 웹에서 P1(§9)이고 **iOS에서는 M4의 명시적 컷 후보**다(08 §3 "M4 iOS" — 지연 시 태그 필터로 대체하고 M5와 병행 이월). 컷되면 iOS는 목록의 `tag` 필터로 재발견을 감당하고, 그 사이 검색 수요는 웹이 백필한다.

## 5. 화면 4 — 태그 (Tags)

**(1) 목적** — 자동 태깅의 재료인 통제 사전(30~50개)을 직접 손보고, 어떤 태그가 실제로 쓰이는지 본다. **이 화면이 facet(태그 색의 근거)을 사용자가 색이 아닌 방법으로 확인하고 바꿀 수 있는 유일한 경로다**(10 §5.5 보조 수단 4).

**(2) 레이아웃**

```
+--------------------------------------------------------------------------------+
| 태그 사전                                              [ + 태그 추가 ]           |
| 42개 · 링크 1,284건                                                            |  mono meta
+--------------------------------------------------------------------------------+
| 이름          분류        별칭(aliases)                          링크    액션   |
| ────────────────────────────────────────────────────────────────────────────── |
| 개발          만드는 것   dev  development  프로그래밍            312    [편집] |
| 쿠버네티스    만드는 것   kubernetes  k8s                          87    [편집] |
| 영상          형식        video                                    64    [편집] |
| 디자인        만드는 것   design                                    0    [편집] |  ← 0건도 여기선 보인다
| 여행          분류 없음   travel                                    3    [편집] |
+--------------------------------------------------------------------------------+
```

**(3) API 필드 매핑**

| UI | 계약 |
|---|---|
| 행 | `GET /api/v1/tags` → `Tag[]` |
| 이름 | `Tag.name` (sans/500) |
| 분류(facet) | `Tag.facet` (`TagFacet` = `craft`/`media`/`life`/`neutral`) — 한글 라벨 `만드는 것`/`형식`/`일 바깥`/`분류 없음` |
| 별칭 | `Tag.aliases[]` — **mono 칩**(기계 매칭용 문자열이므로 R2) |
| 링크 수 | `Tag.link_count` (mono, `tabular-nums`) — 삭제되지 않은 링크 기준 |
| 헤더 요약 | `Tag[].length`, `GET /api/v1/stats` → `total_links` |
| 추가 | `POST /api/v1/tags` `{name, aliases?, facet?}` — `name` 필수, 대소문자 무시 UNIQUE(중복 400). `facet` 생략 시 `neutral` |
| 편집 | `PATCH /api/v1/tags/{id}` `{name?, aliases?, facet?}` |
| 삭제 | `DELETE /api/v1/tags/{id}` — `link_tags`가 FK CASCADE로 함께 삭제 |

**(4) 상호작용**

- 이름 클릭 → `/?tag={name}`로 이동(사전 관리와 탐색을 잇는 동선).
- `편집`은 인라인 확장 행(별도 다이얼로그 없음): 이름 입력 + **분류 select** + 별칭 토큰 입력(`Enter`/쉼표로 토큰 확정, `Backspace`로 마지막 토큰 삭제) + `저장`/`취소`/`삭제`.
- **분류(facet) select는 4지선다 하나다**(`@radix-ui/react-select`, §1.8). 옵션은 `만드는 것(craft)` / `형식(media)` / `일 바깥(life)` / `분류 없음(neutral)` 4개로 고정이며 **자유 입력도, 색 선택기도 없다** — 색은 계약에 없고 클라이언트가 facet에서 토큰으로 매핑한다(10 §5.2). select 아래 한 줄로 판정 기준을 노출한다: "만드는 것 = 작업에 직접 쓰는 레퍼런스 / 형식 = 읽기·보기·듣기 / 일 바깥 = 나에 관한 것." 각 옵션 왼쪽에 그 facet의 미니 칩(fill 1)을 붙여 색과 이름을 같은 줄에서 잇는다.
- **새 태그는 `neutral`로 태어난다.** `+ 태그 추가`의 분류 기본값은 `분류 없음`이고, 사용자가 고르지 않으면 그대로 저장된다(계약 기본값과 동일).
- facet 변경은 낙관 반영한다 — select를 바꾸는 즉시 그 행의 칩 색이 바뀌고 `PATCH {facet}`이 나간다. 실패하면 이전 값으로 롤백 + 에러 토스트. 저장 후 링크 쿼리 캐시(`['links']`, `['search']`)를 무효화한다(행 안의 칩 색이 달라진다).
- 별칭 편집이 정확도에 가장 싸게 기여한다는 사실을 화면이 말한다 — 별칭 입력 아래 한 줄: "별칭은 규칙 태거가 문자열로 매칭하는 대상입니다."
- 삭제는 **확인 다이얼로그 필수**(`AlertDialog`) — **앱 전체에서 확인 다이얼로그를 쓰는 유일한 곳이다**(§1.2, 10 §4.11). 링크 삭제와 달리 여기에는 실행취소 수단이 없다(복원 API 없음 + `link_tags` CASCADE). 문구에 영향 범위를 숫자로 적는다: "`개발`을 삭제하면 링크 312건에서 이 태그가 함께 제거됩니다. 되돌릴 수 없습니다." 숫자는 `Tag.link_count`를 그대로 쓴다. 삭제 버튼은 **10 §4.1의 `danger` 변형**(투명 배경 + `--danger` 텍스트 + `1px --danger` 보더)이고, 취소는 `secondary`이며 기본 포커스는 취소다. **채움 danger 변형은 존재하지 않는다**(10 §2.1.4-b).
- 정렬 토글 2개만: `링크 수` desc(기본) / `이름`. **facet으로 정렬하지 않는다**(10 §5.3 — 색이 위치까지 지배하면 두 채널이 중복된다). **최근 30일 부착 횟수 정렬은 계약에 데이터가 없어 구현하지 않는다**(§10-2).
- 태그 삭제/생성 후 링크 쿼리 캐시(`['links']`, `['search']`)를 무효화한다(칩 표시가 달라진다).

**(5) 상태별**

| 상태 | 표현 |
|---|---|
| 로딩 | 스켈레톤 행 10개 |
| 빈 상태 | "태그 사전이 비어 있습니다. 자동 태깅은 사전에 있는 태그만 붙입니다." + `+ 태그 추가` |
| 생성 에러(중복 400) | 이름 입력 아래 인라인 `warn`: "이미 있는 이름입니다." (대소문자 무시 UNIQUE) |
| facet 변경 실패 | select를 이전 값으로 되돌리고 `error` 토스트. 행의 칩 색도 함께 롤백 |
| 삭제 성공 | 행 제거 + 토스트("`개발`을 삭제했습니다.") — 실행취소 없음(복원 API 없고 CASCADE는 되돌릴 수 없다) |
| 오프라인 | 읽기 유지, `+ 추가`/`편집`/`삭제` 비활성 |

**(6) 반응형** — `< 560`: 테이블이 카드형 2줄 리스트로(1줄: 이름 + 분류 + `link_count`, 2줄: 별칭 가로 스크롤), 액션은 행 우측 `…` 메뉴. `≥ 560`: 5열 테이블(이름·분류·별칭·링크·액션). `≥ 1024`: 목록 콘텐츠 폭(10 §2.3)을 유지한다 — 인스펙터가 없는 화면이라 더 넓히지 않는다.

**(7) 모션** — 인라인 편집 행 펼침은 **`grid-template-rows: 0fr → 1fr`** `--dur-2`(180ms) + 내용 `opacity` `--dur-out`(120ms) 지연 진입이다. **`height`를 애니메이션하지 않는다**(10 §6.1 — `top`/`height` 금지). 행 추가/삭제는 §1.7 표 그대로. 카운트 숫자는 **애니메이션하지 않는다**.

**(8) iOS 차이** — `List` + `EditButton`으로 삭제하고, 별칭 편집은 별도 `NavigationLink` 상세로 밀어 넣는다(작은 화면에서 인라인 확장은 터치 타깃이 무너진다).

**(3) API 필드 매핑** — `GET /api/v1/links/{id}` → `LinkDetail` (`Link` + 상세 필드)

| UI | 필드 | 비고 |
|---|---|---|
| 제목 | `title` | 빈 문자열이면 `domain` → `url` |
| 도메인 / 원문 | `domain` / `url` | `url`은 `target="_blank" rel="noreferrer"` |
| 썸네일 | `thumb_url` | `null`이면 슬롯 제거(회색 박스 남기지 않는다) |
| 태그 칩 | `tags[]`: `id`, `name`, `source`, `confidence` | `role: 'readonly'` — `manual`은 fill 1(그 태그의 facet tint), 그 외는 fill 0. facet은 `GET /api/v1/tags` 캐시로 해석(§3(3)). `confidence`는 `null`이면 `—` |
| 메모 | `note` | 편집 = `PATCH {note}` |
| 설명 | `description` | 상세는 절단 없는 전문 |
| 메타 | `published_at`, `author`, `content_type`, `duration_sec`, `word_count`, `lang` | 폴백 규칙 §1.3 |
| 잡 | `jobs.scrape`(필수), `jobs.tag`, `jobs.thumb` | **필드 부재 ≠ failed.** 부재는 `—`, `failed`는 `danger` 텍스트 |
| 오류 | `error` | 빈 문자열이면 섹션 자체 제거 |
| 상태 | `status` | 인스펙터 상단 좌측 `--size-rail` 레일로 표시(배지 없음). 두께 값과 4상태 색은 10 §2.3 · §4.7 — **행과 같은 두께다** |
| 재시도 | `POST /links/{id}/retry` → `202 {id, status}` | **`status === 'failed'`일 때만 노출.** 그 외엔 400 |
| 삭제 | `DELETE /links/{id}` → `204` | 소프트 삭제 |
| 태그 후보 | `GET /api/v1/tags` → `Tag[]` | 콤보박스 옵션(`Tag.name`으로 필터·표시) |

**(4) 상호작용 — 편집이 여기 통합된다**

- **태그 추가**: `+ 태그 추가` 또는 `E` → **직접 구현한 콤보박스**. Radix에는 Combobox 프리미티브가 없으므로 `Popover` + 텍스트 입력 + 필터 리스트로 ARIA combobox 패턴을 우리가 소유한다(§1.8 — `role="combobox"` + `aria-expanded`/`aria-controls`/`aria-activedescendant`, 리스트는 `role="listbox"`/`role="option"`, `↑↓`로 활성 옵션 이동·`Enter` 확정·`Esc` 닫기). 옵션은 사전(`GET /tags`) 전체이고 입력으로 대소문자 무시 부분 문자열 필터. 선택 즉시 낙관 반영 + `PATCH {tags: [...현재 이름들, 새 이름]}`.
- **사전에 없는 이름을 입력한 경우**: 계약상 `PATCH`는 400이다. 그래서 콤보박스 하단에 `warn` 항목을 하나 띄운다 — "`머신러닝`은 사전에 없습니다. [사전에 추가하고 붙이기]". 실행하면 `POST /api/v1/tags {name}` → 성공 시 이어서 `PATCH {tags}`. 두 요청 중 첫 번째가 실패하면 두 번째를 보내지 않고 인라인 에러.
- **태그 제거**: 칩의 `×` 또는 칩 포커스 후 `Backspace`. `PATCH`는 **남은 이름 배열 전체**를 보낸다(부분 삭제 API 없음). 전부 제거 = `tags: []`(계약상 전체 제거), `null`/생략과 다르다.
- **메모**: blur 또는 `Cmd/Ctrl+Enter`에 저장(§1.2 — 저장 폼 안에서의 즉시 저장). 값이 바뀌지 않았으면 요청하지 않는다. 저장 중에도 입력은 잠그지 않는다.
- **재시도**: `R`. 누르는 즉시 레일이 진행 펄스로 바뀌고 §1.5 폴링이 시작된다. 버튼은 **무채색 outline**(10 §4.1 `secondary`)이다 — 유채 잉크와 danger·warn을 같은 컴포넌트에서 채움색으로 나란히 두지 않는다는 색맹 완화 규칙(10 §2.1.4-b).
- **삭제**: `Backspace`/`Delete`. **확인 다이얼로그 없이 즉시 실행**하고 `undo` 토스트로 되돌린다(지속 시간은 10 §4.10, 되돌리기의 한계 문구는 §1.5). 인스펙터는 닫히고 커서는 다음 행으로 간다.
- `Esc`로 닫힘. 닫혀도 목록 스크롤 위치와 `J`/`K` 커서는 유지된다.
- 딥링크 `/links/123` 직접 진입: 목록을 뒤에 로드하고 인스펙터를 연 상태로 렌더. 뒤로 가기 = 인스펙터 닫기.

## 7. 화면 6 — 태그 편집 (Edit)

**별도 화면을 만들지 않는다.** §0의 결정에 따라 편집 UI는 전부 인스펙터(§6-4) 안에 있다. 이 절은 "편집이 어디로 갔는지" 찾는 사람을 위한 포인터이자, 편집 계약의 함정 3개를 한곳에 모아 둔 곳이다.

| 함정 | 계약 사실 | UI가 지켜야 할 것 |
|---|---|---|
| 전체 교체 | `PATCH {tags}`는 이 링크의 태그를 **전량 교체**한다 | 항상 "현재 화면에 보이는 이름 배열 전체"를 보낸다. 델타를 보내지 않는다 |
| 3-값 구분 | `tags` 생략/`null` = 유지, `[]` = 전체 제거 | 메모만 저장할 때는 `tags` 키를 **아예 넣지 않는다**(빈 배열로 보내면 태그가 날아간다) |
| 사전 강제 | 존재하지 않는 태그 이름이면 400 | 자유 입력을 허용하되 제출 전에 사전 대조 → 없으면 `POST /tags` 경유 흐름으로 유도 |

추가 사실 하나: 수동 편집은 서버에서 `link_tags(source='manual', confidence=NULL)` + `tag_feedback(added/removed)`으로 기록되고 이것이 M5 재랭킹 학습 데이터다. 그래서 `manual` 칩만 채움 1단(그 태그의 facet tint)을 받는 표시(R1)는 장식이 아니라 **학습 데이터를 만들고 있다는 신호**다. 이 표시는 UI에서 되돌릴 수 없다 — `source`를 다시 `rules`로 바꾸는 API는 없다.

**재평가 트리거는 10 §5.2가 원본이다** — `neutral` 칩 40% 초과 / `craft` 75% 초과 두 가지다. 이전의 "`manual` 비율 30% 초과 시 틴트를 인스펙터 전용으로 되돌린다" 트리거는 **폐기됐다**: 채움 1단이 브랜드 액센트가 아니라 그 태그 자신의 facet tint이므로 manual이 늘어도 브랜드 색이 번지지 않는다.

**(3) API 필드 매핑**

| UI | 계약 |
|---|---|
| API 키 저장 | 서버 호출 없음. `localStorage` → 이후 모든 요청의 `Authorization: Bearer` |
| 연결 확인 1단계(생존) | `GET /healthz` (인증 면제) → `{status: "ok"}` |
| 연결 확인 2단계(키 검증) | `GET /api/v1/tags` 1회 — 인증이 필요한 가장 가벼운 엔드포인트. 200이면 키 유효, `401 unauthorized`면 키 불일치 |
| 전체 링크 | `GET /api/v1/stats` → `total_links` |
| 이번 주 | `links_this_week` |
| 최근 30일 스트립 | `by_day[]` = `{date: "YYYY-MM-DD", count}` (localtime) |
| 상위 태그 | `by_tag[]` = `{name, count}` — 상위 5개만, 클릭 시 `/?tag={name}` |

`GET /api/v1/stats`는 계약상 401/404를 낼 수 있다. 401은 §1.4의 키 배너로, 404는 "통계를 사용할 수 없습니다" 한 줄로 처리하고 **섹션 전체를 숨긴다**(에러 블록을 남기지 않는다).

**연결 확인은 2단계다 — `/healthz` 하나로는 키를 검증할 수 없다.** 계약상 `GET /healthz`는 `security: []`, 즉 **인증 면제**다. 키가 틀려도 200이 오므로 이 호출만으로는 "서버 정상"밖에 알 수 없다. 이 화면의 목적은 키가 실제로 통하는지 확인하는 것이므로 순서를 둘로 나눈다.

| 단계 | 호출 | 판정 |
|---|---|---|
| 1 | `GET /healthz` | 200이면 서버 생존 확인 → 2단계로. 응답 없음/네트워크 실패면 즉시 3번 문구 |
| 2 | `GET /api/v1/tags` (Bearer 부착) | 200 → 1번 문구 / `401 unauthorized` → 2번 문구 / 그 외 → `error.message` 한 줄 |

결과 문구는 정확히 3종이다.

1. **서버 정상 · 키 유효** — 무채색. 1·2단계 모두 통과.
2. **서버 정상 · 키 불일치 (401)** — `danger` 한 줄 + `키 다시 입력` 링크(입력에 포커스). 서버는 살아 있으니 "연결 실패"라고 쓰지 않는다.
3. **서버에 연결할 수 없습니다** — `danger` 한 줄. 1단계가 응답을 받지 못한 경우(§1.6 오프라인 바와 같은 원인).

2단계 응답은 태그 쿼리 캐시(`['tags']`)에 그대로 넣는다 — 검증을 위해 버리는 요청이 아니라 실제로 쓰이는 데이터다.

**(4) 상호작용**

- 키 저장 시 `queryClient.invalidateQueries()`로 전체 캐시를 무효화한다(이전 키로 401 난 쿼리가 다시 돈다). 저장 확인은 버튼 옆 `저장됨` 2초 — 토스트 아님(§1.4-1).
- 키 입력은 `type="password"` + `autoComplete="off"`. 우측에 표시/숨김 토글 1개.
- `연결 확인`은 명시적 버튼이고 위 2단계를 순서대로 1회씩 실행한다. 자동 폴링하지 않는다(로컬 서버에 불필요한 트래픽).
- 테마 3-state: 현재 `setThemePref('system')`이 UI에서 도달 불가능한 것은 버그이므로 세그먼트 3개로 노출한다.
- 북마클릿은 `javascript:` 앵커로 제공하고, 드래그 대상임을 옆 문장으로 알린다. 클릭하면 동작하지 않는다는 안내 포함(브라우저 정책).

**(5) 상태별**

| 상태 | 표현 |
|---|---|
| 키 미설정 | 최상단에 `warn` 배너 유지 + 키 입력에 자동 포커스. 통계 섹션은 숨김(401이 뻔하다) |
| 확인 중 | 버튼 내 스피너, 라벨 `확인 중…`(2단계를 합쳐 하나의 진행 상태로 본다) |
| 확인 성공 | `서버 정상 · 키 유효` (무채색 — 성공에 색을 쓰지 않는다) |
| 확인 실패(401) | `danger` 한 줄 `서버 정상 · 키 불일치 (401)` + `키 다시 입력` |
| 확인 실패(응답 없음) | `danger` 한 줄 `서버에 연결할 수 없습니다` |
| 통계 로딩 | 숫자 자리에 스켈레톤 블록(높이 예약). 카운트업 애니메이션 금지 |
| 오프라인 | 연결 확인 버튼만 활성(그게 오프라인 진단이다), 나머지 비활성 |

**(6) 반응형** — 전 구간 단일 컬럼, 최대 폭 `--w-form`(값은 10 §2.3 — 폼 한 줄이 읽기 좋은 폭). `< 560`에서 통계 숫자 2개가 세로로 쌓이고 30일 스트립은 가로 스크롤 없이 칸 폭만 줄인다(칸 최소 폭 `--size-spark-min`, 10 §2.3의 12스텝 명시적 예외).

**(7) 모션** — 테마 전환 시 색상 트랜지션을 **주지 않는다**(전체 화면 크로스페이드는 느리게 느껴지고 `data-loading` 봉인과 충돌한다). 연결 확인 결과 텍스트만 `--dur-2`(180ms) 교체.

**(8) iOS 차이** — 키는 localStorage가 아니라 App Group 공유 Keychain에 들어가고, **테마 토글은 제공하지 않는다**(HIG: 앱별 외관 설정 지양 — 대등한 클라이언트의 명시적 예외).

## 9. 구현 우선순위

기준 3개: (a) 매일 쓰는 동선을 먼저, (b) 계약이 이미 구현된 것을 먼저, (c) 시그니처(S1 레일 / S2 채워지는 행)를 MVP 안에 넣는다 — 나중으로 미루면 영영 안 넣는다.

## 10. 계약 공백 목록 (지금은 못 하는 것과 그 이유)

이 절은 "왜 그 기능이 없냐"에 대한 단일 답변처이고, 스펙을 늘릴지 판단할 때 여기부터 본다. 늘리려면 `api/openapi.yaml`을 먼저 고치고 `just gen` + `just web-gen`으로 따라오게 한다.

**태그 색은 여기 없다 — 공백이 아니라 해결됐다.** 계약이 `TagFacet` enum과 `Tag.facet` / `TagInput.facet`을 갖고, 클라이언트가 facet → 토큰으로 매핑한다(10 §5.2). **`LinkTag`에 `facet`이 없는 것은 누락이 아니라 결정이다** — 목록 화면은 필터 바를 위해 이미 `GET /api/v1/tags` 전량을 들고 있으므로 `Map<tagId, facet>`으로 해결되고, 링크 10만 건 목표에서 `LinkTag`마다 facet 문자열을 실어 보내면 페이로드가 링크당 태그 수만큼 늘어난다. 캐시 미스 시 신규 태그가 잠깐 `neutral`로 렌더되는 것은 **정확한 폴백**이다.

1. **실시간 진행 알림이 없다.** SSE/WebSocket 엔드포인트가 없어 `pending → done` 전이를 폴링으로만 안다(§1.5). 링크 몇 건 수준에서는 폴링이 충분히 싸다. 저장이 하루 수십 건을 넘거나 배치 임포트 진행률이 필요해지면 그때 스펙에 스트림을 추가할 후보다.
2. **태그별 최근 30일 카운트가 없다.** `Tag.link_count`는 전체 누적이고, `Stats.by_day`는 링크 수이지 태그별이 아니다. 그래서 칩·사전 정렬은 `link_count` desc가 최선이다. 클라이언트가 전체 링크를 받아 집계하는 방식은 10만 건 목표와 정면충돌하므로 하지 않는다.
3. **배치 API가 없다.** 삭제/태그 수정이 링크 단위라 다중 선택은 N번의 요청이 된다. 단일 사용자 규모에서 이득이 작아 보류한다.
4. **검색 매칭 구간 정보가 없다.** 응답에 스니펫/오프셋이 없고 `rank`(bm25)만 온다. 클라이언트가 trigram 매칭 구간을 추정해 하이라이트하면 틀린 강조를 만든다 — 하지 않는다.
5. **필터 결과 기준 태그 카운트가 없다.** `link_count`는 전역이므로 "현재 필터 안에서 0건인 칩 숨기기"는 불가능하다. 대신 **전역 `link_count === 0`인 태그만 목록 화면 칩 바에서 숨긴다**(태그 관리 화면에서는 0건도 보여야 한다 — 사전 관리 대상이므로).
6. **소프트 삭제 복원 엔드포인트가 없다.** 실행취소는 동일 `url` 재-POST로 구현하며 `status`가 `pending`으로 돌아간다(§1.5). 이 손실을 UI 문구가 감추지 않는다.
7. **총 건수가 없다.** `LinkPage`는 `links`/`next_cursor`, `SearchPage`는 `mode`/`links`/`next_cursor`뿐이고 어디에도 `total`이 없다 — keyset 커서 페이지네이션은 총계를 세지 않는 것이 성능의 근거다(전체 COUNT는 10만 행 목표와 충돌한다). 그래서 목록·검색 어디에도 "전체 N건"을 쓰지 않고, 표시하는 숫자는 **클라이언트가 지금까지 불러온 누계**뿐이며 라벨로 그 사실을 밝힌다("불러온 N건"). 정말 총계가 필요해지면 `api/openapi.yaml`의 `LinkPage`·`SearchPage`에 `total`을 추가하는 것이 선행 조건이다. (설정 화면의 `Stats.total_links`는 별개다 — 아카이브 전체 누계이지 필터·검색 결과의 건수가 아니다.)
